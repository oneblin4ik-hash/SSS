# SSS — правила работы с дизайном и кодом

Документ для агента и для разработчика: где лежат токены, как устроены
компоненты, и что нужно знать, чтобы переносить макеты из Figma, ничего не
сломав.

---

## Правило владельца: ничего сам, без команды

**Решение владельца, действует во всех чатах по этому репозиторию.** Токены
тратятся только на то, что попросили прямо сейчас. Никакой работы «на всякий
случай», «пока ждём» или «заодно».

Чего не делать **никогда без явной просьбы**:

* **не ставить расписания.** Ни `send_later`, ни `create_trigger`, ни `/loop`,
  ни хуков в `settings.json`. Каждое срабатывание будит сессию и стоит токенов,
  даже когда выясняется, что ничего не изменилось;
* **не подписываться на события GitHub** (`subscribe_pr_activity`). Пуш и PR —
  да, слежение за ними — нет. Владелец смотрит PR сам;
* **не запускать фоновые задачи и подагентов** по своей инициативе;
* **не публиковать артефакты** и не переиздавать существующие. Публикация —
  отдельная просьба, а не способ показать результат;
* **не браться за следующий шаг плана**, закончив предыдущий. Доложить и
  остановиться.

Что делать вместо: закончил задачу — коротко доложи, что сделано и что нужно
от владельца, и жди. Заметил проблему рядом — скажи о ней, не чини молча.

Единственное исключение — то, без чего просьба физически не выполняется:
сборка, тесты и проверка собственной работы перед сдачей (§8.6).

## 0. Главное: одна система Crimson в трёх средах

Палитра, гарнитуры и характер у всех трёх сред общие; разъезжаются только
единицы измерения и способ хранения токенов. Прежде чем верстать, определись,
в какой среде живёт макет — от этого зависит, какой файл токенов править.

| Среда | Где токены | Палитра | Display | Единицы | Что обслуживает |
|---|---|---|---|---|---|
| **Dashboard** | `src/tokens.css` | алый `#D8232A`, фон `#0B0B0C` | Manrope | px | RPG-дашборд продуктивности (`index.html` + `src/`) |
| **Crimson Screen** | `quiz-test/crimson-quiz.css` | алый `#D8232A`, фон `#0B0B0C` | Manrope | px | квиз Telegram Mini App |
| **Crimson Print** | `serbolin-pdf/lib/theme.py` | алый `#D8232A` на белом | Manrope | **mm / pt** | лид-магнит, прежний набор трипваера |
| **Gold Print** | `serbolin-pdf/lib/gold.py` | золото `#D4A843` на `#08080A` | Bebas + Manrope | **px макета → mm** | курс «Первые шаги к форме», 25 листов |

> **Решено владельцем: у курса своя система.** Он переделал трипваер в Claude
> Design и попросил «тёмный премиальный, бенто, стекло, золотые кнопки». Это не
> второй легальный стиль вообще, а стиль одного продукта: курс живёт в золоте,
> всё остальное остаётся в алом. Пересечения нет — `gold.py` не импортирует
> `theme.py` и наоборот.
>
> Пока рядом лежат два набора PDF: старый `tripvaer-*.pdf` (алый, его берут
> лид-магнит, галерея и симулятор бота) и новый `kurs-*.pdf` (золотой). Когда
> новый примут, старый снимается вместе с зависимостями.

> **Решено владельцем: «делай всё в Crimson».** Дашборд переведён с золота на
> алый, Cormorant Garamond заменён на Manrope. Прежняя золотая система в коде
> не осталась нигде — если встретишь янтарь, OKLCH-акцент или засечную
> антикву, это недоделанный кусок, а не второй легальный стиль.

Имена токенов дашборда остались от золотой системы: `--leaf`, `--teal`,
`--crimson`, `--stat-*`. Переименование стоило бы правки 310 обращений в JSX,
поэтому поменялись значения, а не имена. **Читай их по роли, а не по
названию**: `--leaf` — это «положительное», а не «зелёное».

## 1. Определения токенов

### 1.1 Dashboard — CSS custom properties

`src/tokens.css`, единственный блок `:root`. Плоские hex, без OKLCH:

```css
:root {
  --bg-0: #0B0B0C;  --bg-1: #131315;  --bg-2: #1B1B1E;
  --text-1: #FFFFFF; --text-2: #C8C8CE; --text-3: #9A9AA0;

  --accent:    #D8232A;
  --accent-2:  #9E1319;   /* глубокий алый */
  --accent-hi: #F4363D;   /* алый текст на тёмном */

  /* статы различаются насыщенностью одного алого, а не оттенками */
  --stat-strength:   #F4363D;
  --stat-discipline: #D8232A;

  --r-sm: 5px; --r-md: 14px; --r-lg: 20px; --r-xl: 28px;
  --ease-out: cubic-bezier(0.2, 0.8, 0.2, 1);
}
```

Шкала непрерывная: `bg-0…bg-4`, `line-1…3`, `text-1…4`. Новый оттенок заводить
только продолжением шкалы, не отдельным именем.

### 1.2 Crimson Screen — CSS custom properties

`quiz-test/crimson-quiz.css`. Плоские hex, без OKLCH:

```css
:root {
  --void:#0B0B0C; --plate:#131315; --plate-2:#1B1B1E;
  --accent:#D8232A; --accent-hi:#F4363D; --accent-deep:#9E1319;
  --text:#FFFFFF; --text-2:#E6E6E6; --text-5:#6B6B72;
  --r:16px; --r-lg:20px; --r-xl:28px;
}
```

### 1.3 Crimson Print — константы Python

`serbolin-pdf/lib/theme.py`. Токены — модульные константы, а не CSS:

```python
SURFACE   = "#FFFFFF"
INK       = "#111111"   # заголовки страниц
INK_TEXT  = "#222222"   # строки чек-листов
INK_2     = "#4A4A4A"   # текст абзацев
ACCENT    = "#D8232A"
ACCENT_DEEP = "#9E1319" # eyebrow-метки на бумаге
```

**Размеры физические, а не CSS-пиксельные.** Страница описана датаклассом:

```python
A4    = Page("a4",    210, 297, 17, 19, 15, 12)     # кегль 12pt
PHONE = Page("phone", 130, 231, 12, 12, 10, 10.5)
```

### 1.4 Трансформация токенов

Единого пайплайна (Style Dictionary и подобного) **нет**. Есть три ручных моста:

| Мост | Файл | Что делает |
|---|---|---|
| Python → CSS | `serbolin-pdf/lib/theme.py::base_css(page)` | собирает таблицу стилей строкой из констант |
| CSS → HTML квиза | `quiz-test/restyle_quiz.py` | вставляет `crimson-quiz.css` в `<style>` и перекрашивает цвета, зашитые в JS |
| Google Fonts → локальные woff2 | `serbolin-pdf/fetch_fonts.py`, `quiz-test/build_quiz_demo.py` | качает подмножества, для артефактов кодирует в base64 |

Если добавляешь токен в `theme.py` — он попадёт в PDF только через `base_css()`.
Если правишь `crimson-quiz.css` — обязательно прогони `restyle_quiz.py`, иначе
изменение не доедет до `kviz-serbolin.html`.

## 2. Библиотека компонентов

### 2.1 Dashboard — React без модулей

Компоненты — **глобальные функции** в `.jsx`, без `import`/`export`. Babel
превращает JSX прямо в браузере:

```jsx
// src/Logo.jsx
const LogoMonogram = ({ size = 32, accent = "var(--accent)" }) => (
  <svg width={size} height={size} viewBox="0 0 64 64" fill="none">…</svg>
);
```

**Порядок подключения в `index.html` — это и есть система сборки.** Общие
компоненты грузятся раньше страниц, страницы раньше `AppShell.jsx` и `App.jsx`.
Новый компонент требует новой строки `<script type="text/babel" src="…">` в
правильном месте, иначе будет `ReferenceError` в рантайме.

Состав: `Logo.jsx`, `Avatar.jsx` (общие) → `pages/*.jsx` (8 страниц) →
`AppShell.jsx` (сайдбар) → `App.jsx` (роутер на `useState`, монтирование).

### 2.2 Crimson Print — компоненты как функции Python

`serbolin-pdf/lib/components.py` — функции, возвращающие строки HTML:

```python
def checks(items: list[str], big: bool = False) -> str: ...
def numlist(items: list[str]) -> str:      # блок «Что внутри»
def levels_bar(day: int) -> str:           # 4 сегмента прогресса
def figure(kind: str, size_mm: float = 14) -> str:   # SVG-пиктограмма
```

### 2.3 Документация компонентов

Storybook отсутствует, и заводить его некуда — сборки нет. Роль визуального
каталога выполняют:

* `serbolin-pdf/preview/*.png` — растр всех 17 PDF (`python3 preview.py`);
* `quiz-test/shots/*.png` — скриншоты экранов квиза (`test_quiz_demo.py`);
* `shots-dash/*.png` — восемь страниц дашборда (`python3 shot_dashboard.py`);
* `serbolin-pdf/out/kurs-14-dney.html` — все 14 уроков с страницами дней
  одной кликабельной страницей (`python3 build_course.py`);
* `serbolin-pdf/out/bot-simulyator.html` — весь курс так, как он придёт
  в Telegram: покупка, 14 дней, чек-ины, допродажа (`python3 build_bot_sim.py`);
* макеты дизайн-системы: `Crimson Funnel Kit.dc.html` в пакете хендоффа —
  секции «Компоненты вопроса», «Мобильный поток», «Бумага, а не лендинг».

## 3. Фреймворки и сборка

* **React 18** с CDN (`unpkg`, production UMD) + **Babel standalone**.
* **Сборки нет вообще**: ни `package.json`, ни бандлера, ни `node_modules`.
  `index.html` открывается напрямую.
* **Python-тулинг** для PDF: `playwright` (headless Chromium как рендерер),
  `pypdfium2` + `pillow` (растр для визуальной проверки).
* Chromium берётся из образа (`/opt/pw-browsers`), скачивать браузер не нужно.

Следствие: любой инструмент, требующий шага сборки (Tailwind, CSS-модули,
styled-components, TypeScript), в этот репозиторий не заходит без решения
владельца о переезде на бандлер.

## 4. Ассеты

| Что | Где | Как подключено |
|---|---|---|
| Аватар бренда | `serbolin-pdf/assets/avatar.png` (168×168) | в PDF — `<img src="../assets/avatar.png">`; в квизе — base64 в константе `AVATAR_B64` |
| Шрифты | `serbolin-pdf/fonts/*.woff2`, `quiz-test/fonts/*.woff2` | версионируются в git; для артефактов инлайнятся в base64 |
| Готовые PDF | `serbolin-pdf/out/*.pdf` | версионируются — их забирает бот |

**Оптимизации и CDN нет, и это осознанно.** В артефактах на claude.ai работает
строгий CSP: любой внешний хост режется, страница молча уезжает на системный
шрифт. Поэтому всё внешнее превращается во встроенное, а сборка сама проверяет
результат и печатает «Внешних ресурсов нет».

Правило: **фотографии людей не используются**. Единственный «портрет» бренда —
`avatar.png`. Всё остальное рисуется кодом.

## 5. Иконки

Библиотеки иконок нет. Два приёма:

**Векторы, отрисованные кодом** — словарь путей SVG:

```python
# serbolin-pdf/lib/components.py
_FIGURES = {
    "squat":  '<circle cx="40" cy="16" r="8" {h}/><path d="M40 25 …" {s}/>',
    "pushup": '…', "bridge": '…', "lunge": '…', "plank": '…', "walk": '…',
}
```

**Эмодзи** — маркеры четырёх уровней курса: 🔍 Диагностика · ⚙️ Первые шаги ·
🧩 Система · 🛡 Закрепление, плюс ⭐ на дне 12. Рендерятся через системный
Noto Color Emoji и подрезаются классом `.emo` (растровый эмодзи всегда крупнее
букв того же кегля).

> **Расхождение с хендоффом, зафиксированное решением владельца.** Crimson
> прямо запрещает эмодзи и юникод-символы в роли иконок и предписывает Lucide.
> Эмодзи оставлены: они уже есть в текстах спеки, в `TYPES` квиза и в
> сообщениях бота, рядом с которыми лежит PDF. Не «чини» это молча.

**В курсе иначе.** Там эмодзи уровней заменены штриховыми иконками, нарисованными
кодом в `lib/blocks.py` (`_ICONS`): поиск, шестерёнка, пазл, щит и ещё девять.
Так в канве, которую утвердил владелец, и на чёрном листе цветной эмодзи рядом
с золотом выглядел чужеродно.

**Упражнения на странице программы — кадры из видео Эдуарда, а не иконки.**
Двадцать шесть новых фигур рисовать дороже, чем вырезать кадры, и кадр
честнее: человек видит то же тело и тот же зал, что в ролике. Пока кадра нет,
`data/programmy.py` печатает пустое окно с подписью «кадр», а сборка в конце
перечисляет недостающие файлы.

**Исключение — три упражнения, где кадр не сработал.** Планка, горизонтальная
тяга и гиперэкстензия: на снимках движение не читалось, пересъёмки владелец
не планирует. Там рисунок кодом — `lib/blocks.py::figure`, поле `figure`
в атласе, оно старше `frame`. Правило на будущее: рисунок заводится, когда
кадра нет и не будет, а не «чтобы было единообразно» — фотография остаётся
основным вариантом.

Соглашения об именовании: ключи `_FIGURES` — латиницей по названию движения.

## 6. Подход к стилям

### 6.1 Dashboard

Обычный CSS с префиксом `ss-` (`.ss-app`, `.ss-card`, `.ss-btn`, `.ss-sidebar`)
**плюс много инлайновых стилей** — от 13 до 70 вхождений `style={{…}}` на файл
страницы. Ни CSS-модулей, ни CSS-in-JS, ни утилитарных классов.

Глобальные стили и сброс — в конце `src/tokens.css` (box-sizing, `html/body`,
`button`, скроллбар). Компонентные — в `src/app.css`.

### 6.2 Адаптив

В приложении **ровно один медиазапрос**:

```css
@media (max-width: 880px) {
  .ss-app { grid-template-columns: 1fr; }
  .ss-sidebar { position: fixed; bottom: 0; left: 0; right: 0; top: auto; }
}
```

Десктоп — две колонки с сайдбаром, мобильный — одна колонка с нижней навигацией.

PDF не адаптивны by design: страница имеет фиксированный физический размер.
Квиз — одна колонка `max-width: 520px`, растягивается сам.

### 6.3 Правило акцента

Во всех трёх системах: **один акцентный цвет, не больше ~20% площади экрана**,
ровно один следующий шаг на экран. Второго акцента заводить нельзя. Именно
поэтому в квизе цифры плиток белые, а не алые — рядом стоит алая кнопка.

## 8. Перенос макетов из Figma

### 8.1 Сначала определи целевую систему

Спроси (или уточни у владельца), к чему относится фрейм: дашборд, квиз или PDF.
От этого зависит палитра, гарнитура и **единицы измерения**. Ошибка здесь
означает переделку целиком.

### 8.2 Соответствие переменных

Переменные Figma → токены проекта:

| Figma | Dashboard | Crimson Screen | Crimson Print |
|---|---|---|---|
| Background / Surface | `--bg-0…4` | `--void`, `--plate`, `--plate-2` | `SURFACE`, `SURFACE_2` |
| Text primary/secondary | `--text-1…4` | `--text`, `--text-2…5` | `INK`, `INK_TEXT`, `INK_2` |
| Accent | `--accent` | `--accent`, `--accent-hi` | `ACCENT`, `ACCENT_DEEP` |
| Radius | `--r-sm…xl` | `--r`, `--r-lg`, `--r-xl` | `RADIUS["check" \| "util" \| "card"]` |

Прямые hex из Figma в код **не вставляй** — заводи или переиспользуй токен.

### 8.3 Пиксели Figma и печать

Макеты бумажных страниц в хендоффе нарисованы в 420×594 px как превью A4.
Буквально масштабировать их нельзя: получится кегль около 19pt. Порядок такой —

1. правило системы важнее числа из макета: **на A4 текст не мельче 12pt,
   строка до 70 знаков**;
2. остальные размеры переводи как 96dpi (`1px = 0.2646mm`);
3. проверяй результат сборкой — она сама ловит переполнение.

### 8.4 Проверь кириллицу до того, как примешь гарнитуру

Хендофф Crimson назначает display-гарнитурой **Space Grotesk и утверждает, что
кириллица есть у всех трёх гарнитур. Это неверно** — Google Fonts отдаёт для неё
только latin, latin-ext и vietnamese. Весь продукт русскоязычный, поэтому
display везде **Manrope**. Косвенное подтверждение: в самом макете «Бумага, а не
лендинг» один абзац вручную переопределён на `font-family: Manrope`.

Перед тем как взять из Figma новую гарнитуру:

```bash
curl -sS -A "Mozilla/5.0 … Chrome/120" \
  "https://fonts.googleapis.com/css2?family=ИМЯ&display=swap" \
  | grep -oE "^/\* [a-z-]+ \*/" | sort -u
```

Нет `cyrillic` в выводе — гарнитура не подходит, ищи замену.

### 8.5 Новый компонент в дашборде

Сборки нет, поэтому недостаточно создать файл:

1. объявить компонент глобальной функцией (без `export`);
2. добавить `<script type="text/babel" src="src/…">` в `index.html`
   **до** того файла, который его использует.

### 8.6 Проверка перед сдачей

Вёрстка в HTML и то, что печатает Chromium, расходятся регулярно. Никогда не
сдавай PDF, не посмотрев на растр:

```bash
cd serbolin-pdf && python3 build_tripwire.py && python3 preview.py
# «Готово, переполнений нет.» — обязательное условие, но не достаточное
python3 test_profile_parity.py   # квиз и profile.py считают одинаково
python3 build_kurs.py            # курс: свой детектор переполнения
```

У курса лист ужат трансформом: макет нарисован в 1080×1920 px, печатается на
130×231 мм. Поэтому мерить переполнение экранными координатами нельзя —
`build_kurs.py` считает в пикселях макета и падает, если контент не влез.

**Файлов в `out/` больше, чем листов у одного человека.** У курса три оси
вариантов, и сборка делает все версии один раз, а бот отправляет подходящую:

| Ось | Где расходится | Суффикс |
|---|---|---|
| цель | дни 3, 6, 7 — питание | `-nabor` под набор массы |
| пол | дни 4, 9, 11, 13 — базовый комплекс | `-m` / `-zh` |
| место × цель × пол | лист 15, программа тренировок | восемь файлов целиком |

Один связный курс собирает `kurs.book(goal, sex, place)` — из него же
делается `kurs-polnyy.pdf`, чтобы смотреть подряд глазами. Правило простое:
новый вариант заводится функцией страницы с аргументом и суффиксом в слаге,
а не копией файла.

Для квиза:

```bash
cd quiz-test && python3 restyle_quiz.py && python3 build_quiz_demo.py \
  && python3 test_quiz_demo.py     # три типа старта, сверка payload
```

Для дашборда:

```bash
python3 shot_dashboard.py          # 8 страниц в shots-dash/
# «Готово, ошибок в консоли нет.»
```

Скрипт поднимает временный http-сервер и подменяет CDN-ссылки локальными
копиями: на `file://` Babel не может забрать `.jsx` через XHR, а unpkg и
Google Fonts в закрытом окружении недоступны. Сам `index.html` при этом не
меняется — в бою он по-прежнему ходит на CDN.

## 9. Что нельзя менять молча

* **Логика квиза** — `typeOf()`, `plan()`, `bmi()`, `chartMode()`. Ось
  сегментации — опыт (`never` · `quit` · `onoff`), см. §5.1 брифа v2. Порядок
  проверок в `typeOf()` жёсткий: «занимался раньше, бросил» с паузой меньше
  месяца — это не длинная пауза, а те же урывки. `lib/profile.py` повторяет
  эти функции один в один, потому что PDF человек открывает через минуту после
  экрана диагностики и цифры обязаны совпасть. Меняешь в одном месте — меняй
  в обоих, а потом прогоняй `serbolin-pdf/test_profile_parity.py`: он гоняет
  JS квиза в node и сверяет с Python, чтобы расхождение не уехало в прод.
* **Абзац про разрешение врача** при `heart`/`diab` — скопирован из блока
  `.warn` квиза дословно, требование зафиксировано в ТЗ на бота.
* **Тексты из спеки** (`serbolin-pdf/source/*.md`) — переносятся как есть.
  Заново сочинять нельзя; новые тексты пишутся в голосе бренда и прогоняются
  через `/antidetector`.
* **Согласование по роду** — только через `Profile.f(fem, masc)`, оба варианта
  всегда рядом в коде. Страницы трипваера не персонализируются, поэтому там
  нейтральные формы (инфинитивы и существительные).

## 10. Голос бренда

На «ты», по-дружески, с экспертизой. Без канцелярита («данный», «осуществить»,
«в рамках»), без снисходительности, без агрессивных продаж, без таймеров и
«осталось 3 места». Sentence case в заголовках; ALL-CAPS только в мелких
eyebrow-метках. Ошибки — по-человечески.
