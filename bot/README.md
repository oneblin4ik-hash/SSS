# Бот @serbolin_bot

Первый заход: вход, проверка подписки, приём результата теста в базу.
Логика целиком описана в `serbolin-pdf/source/bot-integratsiya-Serbolin.md` —
здесь только код, там источник.

## Как это устроено

Бот живёт на Cloudflare Workers и работает **вебхуком**, а не опросом.
Воркер существует только пока обрабатывает запрос, держать долгое соединение
ему нечем — поэтому Telegram сам стучится к нам при каждом обновлении.

Стоит это ноль рублей: бесплатный тариф даёт 100 000 запросов в сутки
и базу D1 на 5 ГБ.

```
src/index.js      вебхук, разбор обновлений, три сценария
src/telegram.js   обёртка над Bot API и проверка подписки
src/db.js         запись в D1
src/texts.js      все тексты, копия из спеки
schema.sql        таблицы
```

## Что уже работает

* `/start` с диплинком — источник (`quiz`, `q_ig`, `q_yt`, `q_site`) пишется
  в базу при первом заходе и потом не перетирается;
* **гейт по подписке** на `@Serbolin`. Проверка живая, при каждом нажатии:
  запомнить один раз и верить на слово нельзя. Бот обязан быть админом
  канала, иначе Telegram на `getChatMember` не ответит;
* кнопка `Пройти тест` — reply-keyboard с Mini App. Именно reply-keyboard:
  только из неё работает `sendData`, и результат приходит сам, без отдельного
  бэкенда под приём;
* приём результата: payload целиком ложится в `quiz`, имя и пол переезжают
  в `users`, событие `quiz_done` — в ленту;
* **«День 0»** — четыре вопроса свободным текстом, по одному сообщению.
  Ответы разбираются мягко: время сна считается через полночь, окна режутся
  на два. Что не разобралось — идёт в карточку словами человека, а не
  придуманным числом;
* **карточка стартовой точки** и следом **оффер** с подстановкой имени
  и типа старта. Щадящий вариант тренировок обещается только тем, кто сам
  отметил колени или суставы;
* **приписка про врача** при `heart` или `diab` — дословно из квиза.
  Человек читает её на экране диагностики, а через минуту здесь:
  расхождение в формулировке он заметит и решит, что одному из текстов
  верить не надо;
* кнопка **«Написать Эдуарду»** с готовым сообщением и коротким кодом.
  Код стабильный, по нему человек находится в базе;
* **заявка**: по нажатию бот заводит её, шлёт Эдуарду карточку со всем,
  что нужно для разговора, гасит догрев и ставит себе напоминание на два
  часа. Повторное нажатие Эдуарда не будит;
* **кнопки «Включить курс» и «Отказался»** на карточке, `/waiting` со
  списком тех, кто ждёт ответа, напоминание о висящей заявке;
* **догрев** из шести касаний от момента окончания теста. У хвоста —
  кнопка отписки, работает с первого нажатия. Цепочка гаснет, если
  человек оставил заявку или просто написал боту сам.

### Расхождение со спекой, вынужденное

Спека предлагает поставить в оффер url-кнопку `t.me/Mr_Serbolin?text=…`,
чтобы человеку не пришлось придумывать, с чего начать разговор. Мысль
верная, но **у url-кнопки нет обратной связи**: Telegram не сообщает боту,
что по ней нажали. А на этом событии держится вся ручная продажа — карточка
заявки, `/waiting`, напоминание через два часа, остановка догрева.

Поэтому кнопка в оффере обычная, с callback. По нажатию бот заводит заявку
и отдаёт человеку вторым сообщением ссылку в личку с уже набранным текстом.
Лишнее касание взамен на то, что ни одна заявка не потеряется.

## Развернуть

Нужен Node. Всё делается из папки `bot/`.

```bash
npm install                    # ставит wrangler из package.json
npx wrangler login             # откроет браузер, попросит разрешить доступ
```

Дальше во всех командах ниже — `npx wrangler`, а не просто `wrangler`.

**Через панель Cloudflare, без терминала.** Воркер умеет собираться прямо
из репозитория: Compute → Create → Workers → Import a repository, ветка
и `Root directory = bot`. Тогда весь терминал сводится к нулю, а секреты
кладутся в Settings → Variables and Secrets. Схема базы уже накачена.

**1. Создать таблицы.** База уже заведена, `serbolin-bot`, её id прописан
в `wrangler.toml`.

```bash
wrangler d1 execute serbolin-bot --remote --file=schema.sql
```

**2. Положить секреты.** Оба спросятся в терминале и в репозиторий не попадут.

```bash
wrangler secret put BOT_TOKEN
# вставить токен от @BotFather

wrangler secret put WEBHOOK_SECRET
# придумать длинную случайную строку, например из
# `openssl rand -hex 32`, и ЗАПОМНИТЬ — она понадобится на шаге 4

wrangler secret put ADMIN_ID
# Telegram id Эдуарда: сюда приходят заявки и по нему пускают в /waiting.
# Узнать — написать боту /id уже после выкладки.
```

`ADMIN_ID` лежит среди секретов не потому, что он тайна, а потому что
значения из `[vars]` перезаписываются при каждой выкладке, а секреты — нет.

**3. Выложить воркер.**

```bash
wrangler deploy
```

В ответе будет адрес вида `https://serbolin-bot.<аккаунт>.workers.dev`.

**4. Сказать Telegram, куда стучаться.** Подставь свой токен, адрес воркера
и тот самый секрет:

```bash
curl -sS "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "content-type: application/json" \
  -d '{"url":"https://serbolin-bot.<аккаунт>.workers.dev",
       "secret_token":"<WEBHOOK_SECRET>",
       "allowed_updates":["message","callback_query"]}'
```

Должно ответить `{"ok":true,...}`.

**Зачем секрет.** Адрес воркера рано или поздно окажется в чужих руках.
Без этой проверки кто угодно сможет присылать выдуманные обновления от имени
любого человека — например, чужой результат теста. Telegram кладёт секрет
в заголовок каждого запроса, воркер сверяет и молча отбрасывает чужое.

## Проверить

Напиши боту `/start` со второго аккаунта, не подписанного на канал.

1. Приходит приветствие, внизу две кнопки: «Подписаться на канал»
   и «Я подписался». Кнопки теста нет
2. Жмёшь «Я подписался» не подписавшись — всплывает «Пока не вижу подписки»,
   кнопки остаются на месте
3. Подписываешься, жмёшь снова — приходит «Вижу. Погнали», внизу появляется
   кнопка «Пройти тест»
4. Проходишь тест до конца — возвращаешься в чат, приходит подтверждение

Что записалось:

```bash
wrangler d1 execute serbolin-bot --remote \
  --command "SELECT event, at FROM events ORDER BY id DESC LIMIT 20"

wrangler d1 execute serbolin-bot --remote \
  --command "SELECT user_id, type, exp, quiz_at FROM quiz"
```

Живые логи воркера, если что-то не сходится:

```bash
wrangler tail
```

## Если не работает

**Ничего не происходит на `/start`.** Проверь вебхук:

```bash
curl -sS "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

В ответе смотри `last_error_message`. Пусто и `pending_update_count: 0` —
всё в порядке.

**Кнопка теста есть, но подписка не проверяется.** Скорее всего бот не админ
канала. Без прав администратора `getChatMember` на чужой канал не отвечает,
и бот честно считает, что человек не подписан.

**Кнопка «Пройти тест» открывает пустоту.** Mini App грузится только по https
и только с живого адреса. Проверь, что `https://serbolin-kviz.pages.dev/`
открывается в обычном браузере.

## Прогон без развёртывания

```bash
cd bot && node test_bot.mjs
```

Подменяет Bot API и D1 заглушками и проверяет шесть сценариев: чужой запрос
без секрета, вход без подписки, «Я подписался» с подпиской и без, приём
результата теста и битый payload. Не заменяет живую проверку, но ловит
поломки до развёртывания.
