# PDF-выдача воронки Mr. Serbolin

Два продукта: персональный лид-магнит «Твоя диагностика» на выходе из квиза и
комплект трипваера «Первые шаги к форме» — обложка плюс 14 отдельных файлов,
по одному на день.

## Что собирается

| Файл | Формат | Что это |
|---|---|---|
| `out/lid-magnit-demo-galina.pdf` | вертикальный, 5 стр. | лид-магнит, демо на Галине |
| `out/lid-magnit-demo-petr.pdf` | вертикальный, 5 стр. | демо на Петре: мужской род + абзац про врача |
| `out/tripvaer-00-oblozhka.pdf` | вертикальный, тёмная | обложка комплекта |
| `out/tripvaer-01…14-*.pdf` | 14 файлов | страница дня |

Форматы по решению владельца:

* **лид-магнит** — вертикальный «под miniapp», 130 × 231 мм (9:16), читается
  в Telegram свайпом без зума;
* **трипваер — гибрид**: дни 1, 8 и 12 в A4, потому что их реально печатают и
  заполняют ручкой (таблица суток, список покупок, правило возврата «на
  холодильник»); остальные 11 дней — тот же вертикальный формат.

## Сборка

```bash
python3 fetch_fonts.py            # один раз: шрифты в fonts/
python3 build_lead_magnet.py      # оба демо лид-магнита
python3 build_tripwire.py         # обложка + 14 дней
python3 build_tripwire.py 12      # только один день
python3 preview.py                # растр PNG в preview/ — посмотреть глазами
python3 build_course.py           # интерактив: 14 уроков одной страницей
python3 build_bot_sim.py          # симулятор чата с ботом: весь курс целиком
```

`build_bot_sim.py` собирает ленту так, как её увидит ученик в Telegram:
заявка и выдача курса, вопрос про часовой пояс, 14 дней по схеме
«урок → задание → PDF → вечерний чек-ин», четыре экрана уровней и три
касания допродажи. Ответ на чек-ин переключается между «Сделал» и
«Не вышло» — обе ветки видно на одной странице.

Тексты не дублируются: уроки и экраны уровней разбираются из
`source/tripvaer-14-dney-Serbolin.md`, сообщения бота взяты из
`source/bot-integratsiya-Serbolin.md`, имена и размеры PDF читаются
с диска. Своих текстов у симулятора два — вопрос про часовой пояс и строка
вечернего чек-ина; в спеках их нет, и в коде они помечены `WRITTEN_HERE`.

Нужны `playwright` и `pypdfium2` с `pillow`. Chromium берётся из образа
(`/opt/pw-browsers`), скачивать браузер не надо.

Сборка сама сообщает, если контент вылез за поля: у листа стоит
`overflow: hidden`, и переполнение выглядит как молча обрезанный текст, а не
как съехавшая вёрстка. Ловится плохо, поэтому проверяется на каждом прогоне.

```
Готово, переполнений нет.
```

## Персонализация лид-магнита

Плейсхолдеры в формате `{{имя_поля}}`. Полный список с описанием каждого —
в шапке `build_lead_magnet.py`, там же контракт для разработчика бота.

На вход идёт ровно тот JSON, который Mini App отдаёт через `sendData`
(схема — `source/bot-integratsiya-Serbolin.md`, раздел 3). Второго формата
данных нет:

```python
from lib.profile import Profile
from build_lead_magnet import build

payload = json.loads(message.web_app_data.data)
pdf = build(Profile.from_quiz(payload))
await message.answer_document(FSInputFile(pdf))
```

Незаполненный плейсхолдер роняет сборку, а не подставляет пустую строку:
в персональном документе молча выпавшее имя хуже, чем упавший билд.

### Обязательное правило по здоровью

Если в `hl` пришло `heart` или `diab`, в блок 1 добавляется абзац про
разрешение врача. Формулировка скопирована из `.warn` в
`app/kviz-serbolin.html` дословно — этого требуют и ТЗ, и
`bot-integratsiya-Serbolin.md` («продублируй её один в один»). Абзац стоит в
алой рамке основным кеглем, не мелким шрифтом. Проверяется демо-файлом на
Петре.

### Согласование по роду

`Profile.f(fem, masc)` — тот же приём, что `f()` в квизе. Оба варианта
всегда рядом в коде, чтобы при правке текста нельзя было забыть про мужской
род. Страницы трипваера не персонализируются, поэтому написаны в нейтральных
формах (инфинитивы и существительные вместо прошедшего времени); исключение —
`Сделал / Не вышло` в подвале, это дословно кнопки бота из ТЗ.

## Откуда берётся текст

* **Лид-магнит** — «Экран 13. Полная диагностика» из
  `source/lid-magnit-kviz-Serbolin.md`; тексты типов, блоков по цели и абзаца
  про зону взяты из `TYPES`, `GOAL_BLOCK` и `ZONE_TXT` в квизе, потому что там
  они уже с согласованием по роду. Раздел «ЧЕТЫРЕ ТИПА» из спеки больше не
  источник: типы вокруг срывов заменены на три типа старта по опыту
  (бриф v2 §5.1).
* **Трипваер** — подпункты «PDF-страница:» / «PDF:» каждого дня в
  `source/tripvaer-14-dney-Serbolin.md` плюс детали из текста самого урока.
  Полный текст урока в PDF не дублируется: он живёт в сообщении бота, а на
  странице максимум одна врезка с ключевой мыслью.

Придумано по аналогии там, где спека не расписывает содержание: состав
комплекса из 5 упражнений (в уроке дня 4 заданы только ограничения — 20 минут,
дом, без оборудования, без ударной нагрузки), 8 вариантов перекуса для дня 6 и
таблица напитков для дня 3. Калорийность напитков — округлённый ориентир на
порцию, на странице так и подписано.

## Отступления от хендоффа Crimson

Оба вынужденные, оба помечены в коде:

1. **Display-гарнитура — Manrope, а не Space Grotesk.** У Space Grotesk нет
   кириллицы: Google Fonts отдаёт только latin, latin-ext и vietnamese
   (в хендоффе сказано, что кириллица есть у всех трёх гарнитур — это не так).
   Manrope не самодеятельность: тот же хендофф назначает её светлой «печатной»
   схеме («Студия»: Manrope 800/700/400), а наши страницы как раз светлые.
   Основной текст — Inter, как и задумано.
2. **Эмодзи уровней оставлены**, хотя хендофф говорит «без эмодзи совсем».
   Решение владельца: эмодзи уже есть в текстах спеки, в `TYPES` квиза и в
   сообщениях бота, рядом с которыми лежит PDF. Набраны через Noto Color Emoji
   и подрезаны по кеглю — растровый эмодзи всегда выглядит крупнее букв.

Остальное по хендоффу: палитра, архитектура листа (белая бумага, колонтитул,
чек-строки, блок «Заметка», подвал), радиусы, правило «алый только на метках,
чекбоксах и номерах, никогда внутри абзаца».

## Структура

```
lib/theme.py       токены Crimson в печатных единицах + общий CSS
lib/render.py      HTML → PDF через Chromium, детектор переполнения
lib/components.py  шапка, полоса прогресса, подвал, чекбоксы, фигуры упражнений
lib/profile.py     профиль из квиза; ИМТ, тип старта, прогноз — как в квизе
data/days.py       содержимое 14 страниц трипваера
data/lead_magnet_text.py  тексты лид-магнита
```

Фигуры упражнений отрисованы кодом (SVG-контуры), фотографий людей нет — по
решению проекта единственный «портрет» бренда это `assets/avatar.png`.

## Если меняется логика квиза

`lib/profile.py` повторяет `bmi()`, `typeOf()`, `chartMode()` и `plan()` из
`quiz-test/kviz-serbolin.html` один в один. Это принципиально: PDF человек
открывает через минуту после экрана диагностики, и цифры обязаны совпасть.
Поменялась логика в квизе — правится и здесь, места помечены ссылками на
функции оригинала. Порядок проверок в `typeOf()` жёсткий: «бросил, но
последний раз меньше месяца назад» — это не длинная пауза, а те же урывки.

Сверять два языка глазами не нужно:

```bash
python3 test_profile_parity.py
```

Тест вырезает из HTML квиза кусок между «состояние» и «рендер» — в нём вся
арифметика и ни одного обращения к DOM, — выполняет его в node на восьми
профилях и сравнивает с тем, что даёт `Profile` на тех же ответах. Расходятся
тип, срок, число тренировок, ИМТ или режим прогноза — тест падает и говорит,
в каком поле.
