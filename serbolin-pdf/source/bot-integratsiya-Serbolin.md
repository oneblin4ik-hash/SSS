# Квиз → бот: интеграция и тексты

Документ для разработчика бота @Serbolin_bot и для тебя как владельца текстов.
Файл квиза: `kviz-serbolin.html` (Telegram Mini App, один файл, без сборки).

---

## 1. Как устроена связка

```
реклама / канал t.me/Serbolin / сайт serbolin.pro
        │
        ▼
   бот @Serbolin_bot  ──[ кнопка «Пройти тест» ]──►  Mini App (kviz-serbolin.html)
        ▲                                                    │
        │                     результат JSON ◄───────────────┘
        │
   День 0: 4 вопроса в чате  →  карточка стартовой точки  →  оффер 690 ₽
                                                              (кнопка в личку)
        │
        ├── написал ──► оплата в личке ──► Эдуард включает курс ──► 14 дней
        └── молчит ───► догрев +4ч / +24ч / +3д / +7д
```

Одно правило, из которого всё вытекает: **человек не выходит из Telegram ни на одном шаге**. Контакт берётся автоматически из `user_id`, ни телефона, ни почты, ни регистрации.

## 2. Где хостить и как запускать

Mini App — статика. Подойдёт любой https-хостинг: Cloudflare Pages, Netlify, nginx на своём сервере. Один файл, шрифты с Google Fonts.

**Два способа запуска, и они по-разному отдают результат:**

| Способ | Как настраивается | Как приходит результат |
|---|---|---|
| Reply-keyboard кнопка (рекомендую) | `KeyboardButton(text="Пройти тест", web_app=WebAppInfo(url=...))` | `message.web_app_data.data` — работает `sendData`, ничего писать на бэке не надо |
| Menu Button / inline-кнопка | Настраивается в BotFather или `InlineKeyboardButton(web_app=...)` | `sendData` **не работает**. Нужен эндпоинт `CFG.API`, приложение POST-ит туда JSON |

В файле квиза за это отвечает верхний блок:

```js
const CFG = {
  API: "",                  // пусто → уходим через sendData
  FIGURES: { f: [], m: [] } // пути к 3D-фигурам, по 6 на пол
};
```

Ставь reply-keyboard кнопку и оставляй `API` пустым — это самый короткий путь до рабочей воронки. `API` понадобится, если захочешь запускать тест из меню бота или из inline-кнопки в канале.

**Диплинки для рекламы:**

```
t.me/Serbolin_bot?start=quiz          общая
t.me/Serbolin_bot?start=q_ig          из Instagram
t.me/Serbolin_bot?start=q_yt          из YouTube
t.me/Serbolin_bot?start=q_site        с serbolin.pro
```

Источник пишем в БД при первом `/start` — потом видно, откуда приходят те, кто платит.

## 3. Что именно присылает квиз

Компактный JSON, 190–230 байт (лимит `sendData` — 4096, запас огромный).

```json
{"v":1,"n":"Галина","g":"f","a":36,"h":170,"w":62,"wg":58,"gl":"loss",
 "fn":3,"fg":4,"lf":"some","at":"4-6","bp":"2-3w","br":["even","stress"],
 "hl":["knee"],"t":4,"wk":7,"tr":2,"bmi":21.5,"cm":"weight"}
```

| Ключ | Значение | Возможные варианты |
|---|---|---|
| `v` | версия схемы | `1` |
| `n` | имя | строка |
| `g` | пол | `f` · `m` |
| `a` `h` | возраст, рост | числа |
| `w` `wg` | вес сейчас, вес цель | числа |
| `gl` | главная цель | `loss` · `mass` · `tone` · `power` |
| `fn` `fg` | фигура сейчас / цель | `0…5` |
| `lf` | образ жизни | `sit` · `some` · `reg` · `much` |
| `at` | сколько заходов было | `1` · `2-3` · `4-6` · `many` |
| `bp` | **где ломается** | `days` · `week` · `2-3w` · `month` · `none` |
| `br` | что сбивает (до 3) | `even` `tired` `stress` `time` `what` `bored` `fast` |
| `hl` | здоровье | `back` `knee` `heart` `diab` `joint` `food` `none` |
| `t` | тип срыва → уровень курса | `1` · `2` · `3` · `4` |
| `wk` `tr` | недель до цели этапа, тренировок в неделю | числа |
| `bmi` | ИМТ | число |
| `cm` | режим прогноза | `weight` · `form` |

`bp` — самое ценное поле во всей воронке. Из него берётся красная метка на графике, зона риска в тексте и приоритет в курсе. Храни его отдельным полем в БД, по нему потом сегментируешь рассылки.

**Как считается `t`** (квиз уже посчитал, но бот должен понимать логику для рассылок). Порядок проверок жёсткий, точка срыва сильнее образа жизни:

1. `bp = none` → тип 3 «Дисциплина есть, системы нет»
2. `bp` = `2-3w` / `month`, либо `at` = `4-6` / `many` → тип 4 «Начинаю и срываюсь»
3. `bp = days`, либо `at = 1` → тип 1 «Хаотичный старт»
4. `lf` = `reg` / `much` → тип 3
5. иначе → тип 2 «Собираюсь, но не начинаю»

**Обязательное правило по здоровью.** Если в `hl` пришло `heart` или `diab`, бот дописывает к карточке Дня 0 и к первому уроку курса отдельный абзац: нагрузка только после разрешения врача. Формулировка есть в квизе, продублируй её один в один. Курс продавать при этом можно — он про режим, питание и протокол срыва, а не про рекорды. Но фраза должна быть, и не мелким шрифтом: тут вопрос не юридической подстраховки, а того, что человек с диабетом или гипертонией реально может себе навредить, если начнёт с интервалов по видео из интернета.

**Безопасность.** Если используешь `CFG.API`, бэкенд обязан проверить `initData` подписью (HMAC-SHA256 на секрете из токена бота) и брать `user_id` оттуда, а не из тела запроса. Иначе любой сможет прислать результат за чужого человека.

## 4. Обработчики (aiogram 3, скелет)

```python
from aiogram import F, Router
from aiogram.types import Message, ReplyKeyboardMarkup, KeyboardButton, WebAppInfo
import json

r = Router()
QUIZ_URL = "https://serbolin.pro/quiz/"

@r.message(CommandStart())
async def start(m: Message, command: CommandObject):
    src = command.args or "direct"
    await db.upsert_user(m.from_user.id, source=src)
    kb = ReplyKeyboardMarkup(
        keyboard=[[KeyboardButton(text="Пройти тест", web_app=WebAppInfo(url=QUIZ_URL))]],
        resize_keyboard=True
    )
    await m.answer(TXT_WELCOME, reply_markup=kb)

@r.message(F.web_app_data)                       # результат теста
async def quiz_done(m: Message):
    res = json.loads(m.web_app_data.data)
    await db.save_quiz(m.from_user.id, res)
    await start_day0(m, res)                     # сразу первый вопрос Дня 0
```

Родовые формы. Один хелпер решает всю проблему разом:

```python
def g(res, fem, masc): return fem if res["g"] == "f" else masc
# g(res, "уходила", "уходил")
```

## 5. Тексты бота

### 5.1 Приветствие (`TXT_WELCOME`)

> Всем привет кто здоров и болен, на базе Эдуард Серболин.
>
> 12 лет тренирую людей онлайн, за это время прошло больше тысячи человек. И почти каждый приходил с одной и той же фразой: «я уже пробовал(а), у меня не получается».
>
> Получается. Просто ломается всегда в одном и том же месте, и это место можно найти заранее.
>
> Жми кнопку внизу. 14 вопросов, две с половиной минуты — и я скажу, на какой неделе ты обычно сходишь с дистанции и что с этим делать.

### 5.2 День 0 — четыре вопроса

Задавать по одному сообщению, ответы свободным текстом, ждать каждый.

> **День 0. Твоя стартовая точка**
>
> Ни диеты. Ни тренировки. Ни весов.
>
> Прошлые заходы начинались одинаково: «с понедельника меняю всё». И заканчивались одинаково. Поэтому сегодня не меняем ничего — только смотрим, с чем работаем.
>
> Четыре вопроса. Отвечай как есть, редактировать не надо.

1. > Во сколько ты сегодня {g:встала|встал} и во сколько {g:легла|лёг} спать?
2. > Какие два окна по 20–30 минут в твоём дне реально свободны? Не «можно найти», а именно свободны.
3. > В какое время суток тебя чаще всего пробивает на еду?
4. > Что ты {g:съела|съел} вчера после 19:00? Честно.

### 5.3 Карточка стартовой точки

Собирается из четырёх ответов. Числа берём из ответа человека, ничего не досочиняем.

> **{name}, твоя стартовая точка**
>
> **Режим:** подъём {подъём}, отбой {отбой} → {часы} сна. {если <7ч: «Мало. При таком сне вечерний голод почти неизбежен: организм добирает энергию едой.» / если ≥7ч: «Нормально. С таким сном работать проще.»}
> **Твои окна:** {окно1} и {окно2}. Тренировки ставим сюда, обеденное время не трогаем.
> **Зона риска:** {время голода}.
> **Вчера вечером:** {ответ}
>
> Смотри, что произошло. Ты не {g:села|сел} на диету и не {g:пошла|пошёл} в зал, а на руках у тебя то, чего не было ни в одном прошлом заходе: конкретное место поломки и конкретные окна под нагрузку.
>
> Это был День 0. Самый простой день моей системы.

Дальше сразу оффер, отдельным сообщением.

### 5.4 Оффер (690 ₽)

> **«План на первые 14 дней»**
>
> 14 дней. Один короткий урок в день и одно действие. Не теория, а то, что делаешь сегодня.

> 🔍 **Диагностика** (дни 1–3) — где ты стоишь, без диеты и зала

> — 14 PDF-страниц, по одной на день

>
> **690 ₽** вместо ~~1 990 ₽~~ — один раз, навсегда твоё. Это стартовая цена: как только курс обкатается, он будет стоить 1 990 ₽.
>
> `[ Написать Эдуарду ]`
>

Уровень подставляется по `t`: 1 → 🔍 Диагностика (дни 1–3) · 2 → ⚙️ Первые шаги (4–7) · 3 → 🧩 Система (8–10) · 4 → 🛡 Закрепление (11–14).

### 5.5 Догрев, если не купил

Отменять всю цепочку, как только человек нажал «Написать Эдуарду»: дальше
разговор идёт в личке, и автоматические напоминания там только мешают.
Джобы вешаются от `quiz_at` — момента, когда человек дошёл до конца теста.

**+4 часа**
> {name}, карточка со стартовой точкой у тебя на руках. Что с ней делать дальше — покажет День 1: полный аудит режима, без единого запрета. 690 ₽ вместо 1 990 ₽.

**+24 часа**
> Ты знаешь свою зону риска — {зона}. Знаешь свои окна: {окно1} и {окно2}. Через две недели ты про это забудешь, как забывала прошлые разы, — не из-за лени, а потому что напоминать некому. Курс напоминает каждый день. 14 дней, 690 ₽.

**+3 дня**
> Больше на эту тему писать не буду: либо сейчас, либо в другой раз. Если появятся вопросы — я на месте и отвечаю сам. Разбор ситуации бесплатный и без срока.

**+7 дней**
> Прошла неделя. Как дела с теми двумя окнами, {окно1} и {окно2}, — используешь? Если нет, я не удивлён: без структуры они и не должны были заработать. Курс на месте, разбор тоже. Просто напиши.

#### Длинный хвост

Первые четыре сообщения закрывают первые двое суток, пока разбор ещё свежий. Дальше человек не «горячий лид», а просто читатель, который однажды прошёл тест. Пишем редко и по делу, иначе бота отправят в блок и адрес сгорит навсегда.

Правила хвоста, их нарушать нельзя:

* **не чаще раза в две недели**, всего четыре касания, потом тишина;
* **«скоро подорожает» повторяем не больше одного раза** — если бот полгода пишет «бери, пока не подняли», а цена стоит на месте, человек видит, что его водят. Либо цена действительно поднимается, либо эта строка из хвоста уходит;
* **в каждом сообщении хвоста — строка отписки.** `[ Не писать больше ]` выключает всю цепочку и ставит `unsub = true`. Кнопка обязана работать с первого нажатия;
* если человек ответил в чат — цепочка останавливается, дальше живой разговор.

**+14 дней**
> {name}, две недели назад ты {g:прошла|прошёл} тест. Вопрос без продажи: {g:начала|начал} что-то делать или пока думаешь? Если пока думаешь — это нормально, я к тому, что думать можно бесконечно, а День 1 занимает пятнадцать минут.
>
> `[ Написать Эдуарду ]` `[ Не писать больше ]`

**+30 дней**
> Месяц. Твоя зона риска была {зона} — она никуда не делась, я по опыту знаю. Не покупай ничего, просто ответь себе: за этот месяц стало лучше или так же? Если так же — дело не в мотивации, а в том, что не на чем держаться.
>
> `[ Написать Эдуарду ]` `[ Не писать больше ]`

**+60 дней**
> Два месяца назад ты {g:искала|искал} способ начать. Если {g:нашла|нашёл} — рад, правда. Если нет — у меня есть бесплатный разбор, и это не воронка: сажусь, смотрю твою ситуацию, говорю, что делать. Беру несколько в неделю.
>
> `[ Записаться на разбор ]` `[ Не писать больше ]`

**+90 дней — последнее**
> Последнее сообщение от меня, дальше не пишу. Курс и разбор на месте, найти можно в любой момент. Удачи, {name}.

После +90 дней джобы не ставятся. Возобновить цепочку может только сам человек — новым тестом или сообщением в чат.

## 6. Продажа в личке

Платёжной системы нет. Кнопка под оффером ведёт в диалог с Эдуардом, там он
называет реквизиты, отвечает на вопросы и включает курс руками. Ни ЮKassa, ни
провайдерского токена, ни `pre_checkout`, ни `successful_payment` в боте нет.

### 6.1 Кнопка

Обычная url-кнопка с заранее набранным текстом. Человек не должен придумывать,
с чего начать разговор, — у него открывается диалог, где сообщение уже
написано, остаётся нажать «отправить».

```python
code = short_code(uid)          # 4 символа, стабильные для этого user_id
text = quote(f"Хочу курс «План на первые 14 дней». Код {code}")
InlineKeyboardButton(
    text="Написать Эдуарду",
    url=f"https://t.me/Mr_Serbolin?text={text}",
)
```

Код нужен, чтобы Эдуард в личке сразу понимал, кто пишет. Юзернейма может не
быть, имя в Telegram может не совпадать с именем из теста, а `user_id` в личку
не передаётся — без кода придётся переспрашивать «а вы тест проходили?».

`short_code` — любая короткая стабильная функция от `user_id`, например первые
четыре символа sha1. Требование одно: по коду находится человек в базе.

### 6.2 Заявка

Нажатие на кнопку — это событие, которое видит бот. По нему он делает две вещи.

**Пишет Эдуарду карточку.** Всё, что нужно для разговора, сразу под рукой:

> 🔔 Заявка · код **A7F3**
>
> Галина, @galina_ok, 36 лет
> Тип: 🛡 Начинаю и срываюсь · уровень 4
> Рост 165, вес 78 → 66. ИМТ 28.7
> Окна: 7:30 и 20:00 · зона риска: вечер
> Тест пройден 40 минут назад
>
> `[ Включить курс ]` `[ Отказался ]`

**Ставит человеку метку `awaiting`** — заявка есть, курс не выдан.

### 6.3 Выдача

Эдуард жмёт `Включить курс` — бот отменяет догрев, спрашивает часовой пояс и
ставит 14 джобов. Дальше всё как при автоматической оплате.

Кнопка `Отказался` тоже нужна: без неё непонятно, человек ещё думает или уже
сказал «нет», и он будет вечно висеть в списке ожидающих.

### 6.4 Чтобы никто не потерялся

Ручная выдача ломается не на технике, а на памяти. Три вещи закрывают это:

* **`/waiting`** — список тех, кто нажал кнопку и ещё не получил курс, с
  временем заявки. Открыл — видно, кому не ответил.
* **Напоминание Эдуарду через 2 часа**, если заявка всё ещё висит. Не человеку,
  а себе: «Заявка A7F3 без ответа 2 часа».
* **Ничего не удалять по таймауту.** Заявка живёт, пока по ней не нажали одну
  из двух кнопок.

### 6.5 Что остаётся на Эдуарде

Реквизиты он называет сам в переписке, в боте их нет — так их не увидит тот,
кто просто листает оффер.

**Чек обязателен и здесь.** Перевод на карту не отменяет обязанности выдать чек
при продаже физлицу: самозанятость и чек в «Мой налог» на каждую оплату. Разница
с автоматикой только в том, что раньше чек пробивала касса, а теперь это минута
руками после каждой продажи.

`TXT_PAID` — то же сообщение, что и при автоматической оплате, отправляется по
нажатию `Включить курс`:

> {name}, ты в деле.
>
> Первый урок придёт завтра в 8 утра. Ничего сегодня не начинай — серьёзно, не начинай. День 1 идёт без диеты и без зала, и это не подарок, а часть метода: пять изменений одновременно не выдерживает никто.
>
> Терпение + Дисциплина = Результат. До завтра.

Если сегодня уже позже 20:00 — предупредить, что первый урок утром через день, чтобы человек не ждал письма ночью.

### 6.6 Когда переходить на автоматику

Ручная продажа упирается в одно: заявка в час ночи ждёт до утра, и часть людей
за это время остывает. Пока заявок несколько в день, живой разговор это
окупает — он закрывает возражения, которых кнопка не видит. Когда заявки пойдут
десятками и ответы начнут задерживаться на полдня, включается раздел «Оплата» из
автоматической версии: код бота меняется в одном месте, всё остальное остаётся.

## 7. Выдача курса

**8:00 по времени человека.** Часовой пояс спрашивается кнопками один раз — в
момент, когда Эдуард нажал «Включить курс».

Каждый день:
1. Текст урока — одно сообщение, 5 минут чтения (тексты в `tripvaer-14-dney-Serbolin.md`)
2. PDF-страница дня — отдельным документом
3. **20:00 — чек-ин:** инлайн-кнопки `Сделал` / `Не вышло`

Реакции на чек-ин:

> **Сделал** → Отметил. {стрик} день подряд. Так и держим.
>
> **Не вышло** → Бывает. Ничего не компенсируем и не догоняем: завтра просто идём по плану. Один пропущенный день ничего не решает, решает выход из графика на неделю.

Ответ на «Не вышло» ни при каких условиях не должен звучать как упрёк. Именно на этом месте люди отваливаются от курсов, а у нас на 12-й день стоит протокол срыва, который весь построен на «один вечер не равен провалу». Тон должен совпадать заранее.

**День 14** — итоги Точка А → Точка Б, честные границы курса и приглашение на бесплатный разбор.
**Дни 15, 18, 25** — три касания с предложением онлайн-ведения.

## 8. Что писать в БД

```
users:      user_id, name, gender, source, tz, created_at
quiz:       user_id, весь payload как JSONB, type, break_point, quiz_at
day0:       user_id, wake, sleep, window1, window2, hunger_time, dinner_txt
orders:     user_id, code, status (awaiting/paid/declined), amount, at
progress:   user_id, day, checkin (done/failed/null), at
```

События для аналитики: `start`, `quiz_open`, `quiz_step_N`, `quiz_done`, `day0_done`, `offer_shown`, `contact_clicked`, `course_granted`, `declined`, `day_N_read`, `checkin_done`, `checkin_failed`, `review_requested`.

Главные три цифры на старте: **дошёл до конца теста / сделал День 0 / написал в личку**. Четвёртая появляется сразу за ними и на ручной продаже важнее всех: **сколько заявок дошло до оплаты**. Если люди пишут, но не платят — разговор ломается там, где раньше стояла кнопка. Если тест бросают — смотри на каком шаге, экраны 8–11 самые тяжёлые. Если делают День 0, но не платят — проблема в оффере, а не в трафике.
