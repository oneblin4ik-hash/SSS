# Квиз → бот: интеграция и тексты

Документ для разработчика бота @Serbolin_bot и для тебя как владельца текстов.
Файл квиза: `kviz-serbolin.html` (Telegram Mini App, один файл, без сборки).

---

## 1. Как устроена связка

```
реклама / канал t.me/Serbolin / сайт serbolin.pro
        │
        ▼
   бот @Serbolin_bot  ──[ подписан на канал? ]──┬─ нет ─► экран подписки
                                                │
                              [ Пройти тест ] ◄─┘ да
                                    │
                                    ▼  Mini App (kviz-serbolin.html)
        ▲                                                    │
        │                     результат JSON ◄───────────────┘
        │
   День 0: 4 вопроса в чате  →  карточка стартовой точки  →  оффер 1 890 ₽
                                                              (кнопка в личку)
        │
        ├── написал ──► оплата в личке ──► Эдуард включает курс ──► 14 дней
        └── молчит ───► догрев +4ч / +24ч / +3д / +7д
```

Одно правило, из которого всё вытекает: **человек не выходит из Telegram ни на одном шаге**. Контакт берётся автоматически из `user_id`, ни телефона, ни почты, ни регистрации.

## 2. Где хостить и как запускать

Mini App — статика. Подойдёт любой https-хостинг: Cloudflare Pages, Netlify, nginx на своём сервере. Один файл, шрифты с Google Fonts.

**Два способа запуска, и они по-разному отдают результат:**

| Способ | Как настраивается | Как приходит результат |
|---|---|---|
| Reply-keyboard кнопка (рекомендую) | `KeyboardButton(text="Пройти тест", web_app=WebAppInfo(url=...))` | `message.web_app_data.data` — работает `sendData`, ничего писать на бэке не надо |
| Menu Button / inline-кнопка | Настраивается в BotFather или `InlineKeyboardButton(web_app=...)` | `sendData` **не работает**. Нужен эндпоинт `CFG.API`, приложение POST-ит туда JSON |

В файле квиза за это отвечает верхний блок:

```js
const CFG = {
  API: "",                  // пусто → уходим через sendData
  FIGURES: { f: [], m: [] } // пути к 3D-фигурам, по 6 на пол
};
```

Ставь reply-keyboard кнопку и оставляй `API` пустым — это самый короткий путь до рабочей воронки. `API` понадобится, если захочешь запускать тест из меню бота или из inline-кнопки в канале.

**Диплинки для рекламы:**

```
t.me/Serbolin_bot?start=quiz          общая
t.me/Serbolin_bot?start=q_ig          из Instagram
t.me/Serbolin_bot?start=q_yt          из YouTube
t.me/Serbolin_bot?start=q_site        с serbolin.pro
```

Источник пишем в БД при первом `/start` — потом видно, откуда приходят те, кто платит.

## 2а. Проверка подписки на канал

Кнопка теста не показывается, пока человек не подписан на
[t.me/Serbolin](https://t.me/Serbolin). Проверка живая, при каждом нажатии, —
не запоминаем один раз и не верим на слово.

### Что нужно от Telegram

**Бот должен быть админом канала.** Без прав администратора `getChatMember`
на чужой канал не ответит. Достаточно роли без единого разрешения: боту нужно
только читать состав, публиковать он ничего не будет.

```python
CHANNEL = -1001234567890      # numeric id, не @username: у приватного канала
                              # юзернейма нет, а у публичного он может смениться

SUBSCRIBED = {"creator", "administrator", "member"}

async def is_subscribed(uid: int) -> bool:
    try:
        m = await bot.get_chat_member(CHANNEL, uid)
    except TelegramBadRequest:
        return False          # человека нет в канале — API отвечает ошибкой
    if m.status == "restricted":
        return m.is_member    # ограничен, но может всё ещё числиться в канале
    return m.status in SUBSCRIBED
```

Статусы `left` и `kicked` — не подписан. `restricted` разбирается отдельно:
человек может быть в канале и при этом лишён права писать, для нас он
подписчик.

### Экран до подписки

Приветствие показываем целиком — человек должен понять, ради чего его просят
подписаться. Меняется только концовка и кнопки.

Вместо `Пройти тест`:

> `[ Подписаться на канал ]` `[ Я подписался ]`

И строка вместо последнего абзаца приветствия:

> Тест живёт в моём канале — там же разборы, ошибки и то, что не помещается
> в бота. Подпишись, и я открою вопросы.

### Когда человек нажал «Я подписался»

Проверяем заново. Дальше два исхода.

**Подписан** — сразу показываем кнопку теста и приветственную строку:

> Вижу. Погнали: 14 вопросов, две с половиной минуты.

**Не подписан** — без упрёка и без повтора всей простыни:

> Пока не вижу подписки. Если только что подписался — Telegram иногда думает
> пару секунд, нажми ещё раз.

**Считать нажатия не нужно.** Никаких «ты уже третий раз жмёшь» — человек может
искренне не понять, куда нажимать, и злить его на входе бессмысленно.

### Три места, где это ломается

**Задержка Telegram.** Между подпиской и ответом `getChatMember` проходит
секунда-другая. Человек жмёт «Я подписался» слишком быстро и видит отказ.
Лечится текстом выше и тем, что кнопка остаётся на месте.

**Отписался после теста.** Проверка на входе не держит его в канале навсегда.
Это нормально и не чинится: перепроверять на каждом шаге — значит выкидывать
человека из середины воронки, и он не вернётся ни в канал, ни в бота.

**Приватный канал.** Кнопка `Подписаться` ведёт не на `t.me/Serbolin`, а на
инвайт-ссылку. Ссылку класть в конфиг, а не в текст сообщения: её меняют
чаще, чем тексты.

### Что писать в БД

Отдельным событием: `sub_required` — показали экран подписки,
`sub_ok` — проверка прошла. Разница между ними и есть цена гейта: сколько
людей упёрлось в подписку и не пошло дальше.

## 3. Что именно присылает квиз

Компактный JSON, 190–230 байт (лимит `sendData` — 4096, запас огромный).

```json
{"v":2,"n":"Галина","g":"f","a":36,"h":165,"w":78,"wg":66,"gl":"loss",
 "zn":"belly","fn":4,"fg":2,"ex":"quit","ls":"m1","dd":"home","mn":"30",
 "fq":"2","hl":["knee"],"t":"onoff","wk":22,"tr":2,"bmi":28.7,"cm":"weight"}
```

| Ключ | Значение | Возможные варианты |
|---|---|---|
| `v` | версия схемы | `2` |
| `n` | имя | строка |
| `g` | пол | `f` · `m` |
| `a` `h` | возраст, рост | числа |
| `w` `wg` | вес сейчас, вес цель | числа |
| `gl` | главная цель | `loss` · `mass` · `tone` |
| `zn` | акцент на зону | `belly` · `legs` · `top` · `back` · `all` |
| `fn` `fg` | фигура сейчас / цель | `0…5` |
| `ex` | **опыт** | `never` · `quit` · `onoff` |
| `ls` | когда последний раз | `m1` · `m6` · `y1` · `long`, у `never` — `null` |
| `dd` | что именно делал | `gym` `home` `cardio` `group` `diet` `sport`, у `never` — `null` |
| `pl` | где собирается заниматься | `home` · `gym` · `any` |
| `mn` | минут на тренировку | `15` · `30` · `45` · `90` |
| `fq` | раз в неделю | `1` · `2` · `3` · `4+` |
| `hl` | здоровье | `back` `knee` `heart` `diab` `joint` `food` `none` |
| `t` | тип старта | `never` · `quit` · `onoff` |
| `wk` `tr` | недель до цели этапа, тренировок в неделю | числа |
| `bmi` | ИМТ | число |
| `cm` | режим прогноза | `weight` · `form` |

`ex` — самое ценное поле во всей воронке. Оно задаёт весь разбор: и текст типа, и подпись к отметке на графике, и приоритет в курсе. Храни его отдельным полем в БД, по нему потом сегментируешь рассылки.

**Что изменилось в v2.** Ветка про срывы убрана целиком: полей `lf`, `at`, `bp`, `br` больше нет, вместо них пришли `ex`, `ls`, `dd`, `mn`, `fq`, `zn`. Поле `t` стало строкой вместо числа — старые записи со значениями `1…4` относятся к прежней сегментации и в новую не переводятся. Цель `power` из теста убрана.

**Как считается `t`** (квиз уже посчитал, но бот должен понимать логику для рассылок). Порядок проверок жёсткий:

1. `ex = never` → `never` «Чистый лист»
2. `ex = quit` и при этом `ls = m1` → `onoff`: пауза меньше месяца — это не возвращение, а те же урывки
3. иначе → значение `ex` как есть (`quit` «Второй заход» либо `onoff` «Рывками»)

**Акцент на зону — не обещание.** `zn` попадает в разбор отдельным абзацем и в тренировку дополнительным движением. Обещать курс «под ягодицы» или «под живот» нельзя: за 14 дней зону не переделать, а точечно жир не сгоняется. Формулировка есть в квизе, держись её.

**Обязательное правило по здоровью.** Если в `hl` пришло `heart` или `diab`, бот дописывает к карточке Дня 0 и к первому уроку курса отдельный абзац: нагрузка только после разрешения врача. Формулировка есть в квизе, продублируй её один в один. Курс продавать при этом можно — он про режим, питание и первые шаги, а не про рекорды. Но фраза должна быть, и не мелким шрифтом: тут вопрос не юридической подстраховки, а того, что человек с диабетом или гипертонией реально может себе навредить, если начнёт с интервалов по видео из интернета.

**Безопасность.** Если используешь `CFG.API`, бэкенд обязан проверить `initData` подписью (HMAC-SHA256 на секрете из токена бота) и брать `user_id` оттуда, а не из тела запроса. Иначе любой сможет прислать результат за чужого человека.

## 4. Обработчики (aiogram 3, скелет)

```python
from aiogram import F, Router
from aiogram.types import Message, ReplyKeyboardMarkup, KeyboardButton, WebAppInfo
import json

r = Router()
QUIZ_URL = "https://serbolin.pro/quiz/"

@r.message(CommandStart())
async def start(m: Message, command: CommandObject):
    src = command.args or "direct"
    await db.upsert_user(m.from_user.id, source=src)
    kb = ReplyKeyboardMarkup(
        keyboard=[[KeyboardButton(text="Пройти тест", web_app=WebAppInfo(url=QUIZ_URL))]],
        resize_keyboard=True
    )
    await m.answer(TXT_WELCOME, reply_markup=kb)

@r.message(F.web_app_data)                       # результат теста
async def quiz_done(m: Message):
    res = json.loads(m.web_app_data.data)
    await db.save_quiz(m.from_user.id, res)
    await start_day0(m, res)                     # сразу первый вопрос Дня 0
```

Родовые формы. Один хелпер решает всю проблему разом:

```python
def g(res, fem, masc): return fem if res["g"] == "f" else masc
# g(res, "уходила", "уходил")
```

## 5. Тексты бота

### 5.1 Приветствие (`TXT_WELCOME`)

> Всем привет кто здоров и болен, на базе Эдуард Серболин.
>
> 12 лет тренирую людей онлайн, за это время прошло больше тысячи человек. И почти каждый приходил с одной и той же фразой: «я уже пробовал(а), у меня не получается».
>
> Получается. Просто ломается всегда в одном и том же месте, и это место можно найти заранее.
>
> Жми кнопку внизу. 14 вопросов, две с половиной минуты — и я скажу, на какой неделе ты обычно сходишь с дистанции и что с этим делать.

Последний абзац подменяется, если человек не подписан на канал, — см. раздел 2а.

### 5.2 День 0 — четыре вопроса

Задавать по одному сообщению, ответы свободным текстом, ждать каждый.

> **День 0. Твоя стартовая точка**
>
> Ни диеты. Ни тренировки. Ни весов.
>
> Прошлые заходы начинались одинаково: «с понедельника меняю всё». И заканчивались одинаково. Поэтому сегодня не меняем ничего — только смотрим, с чем работаем.
>
> Четыре вопроса. Отвечай как есть, редактировать не надо.

1. > Во сколько ты сегодня {g:встала|встал} и во сколько {g:легла|лёг} спать?
2. > Какие два окна по 20–30 минут в твоём дне реально свободны? Не «можно найти», а именно свободны.
3. > В какое время суток тебя чаще всего пробивает на еду?
4. > Что ты {g:съела|съел} вчера после 19:00? Честно.

### 5.3 Карточка стартовой точки

Собирается из четырёх ответов. Числа берём из ответа человека, ничего не досочиняем.

> **{name}, твоя стартовая точка**
>
> **Режим:** подъём {подъём}, отбой {отбой} → {часы} сна. {если <7ч: «Мало. При таком сне сильнее тянет на еду: организм добирает энергию, которой не хватило от сна.» / если ≥7ч: «Нормально. С таким сном работать проще.»}
> **Твои окна:** {окно1} и {окно2}. Тренировки ставим сюда, обеденное время не трогаем.
> **Зона риска:** {время голода}.
> **Вчера вечером:** {ответ}
>
> Смотри, что произошло. Ты не {g:села|сел} на диету и не {g:пошла|пошёл} в зал, а на руках у тебя то, чего не было ни в одном прошлом заходе: конкретное место поломки и конкретные окна под нагрузку.
>
> Это был День 0. Самый простой день моей системы.

Дальше сразу оффер, отдельным сообщением.

### 5.4 Оффер (1 890 ₽)

> **«Первые шаги к форме»**
>
> 14 дней — с чего начать и как не бросить. Один короткий урок в день и одно действие, а не теория на потом.
>
> 🔍 **Точка старта** (дни 1–3) — где ты сейчас, без диеты и без зала
> ⚙️ **Первые шаги** (4–7) — первая тренировка, день отдыха, вечерняя еда без голодания

> 🛡 **Уже привычка** (11–14) — тренировка когда некогда, как не бросить, тест прогресса
>
> **{name}, по тесту твой старт — {тип}.** Первые три дня одинаковые для всех: смотрим твой день, без диеты и без зала. Дальше упор туда, что в твоём случае решает.
>
> **Что у тебя будет на руках через 14 дней:**
>

> — библиотека из 9 блюд: три завтрака, три обеда, три ужина, которые ты умеешь и любишь

> — схема вечерней еды: без «после шести нельзя», с опорой на твою норму КБЖУ
> — правило возврата на 4 шага: чтобы пропущенный день не превращался в брошенный месяц
> — 14 PDF-страниц, по одной на день
>
> Через две недели курс закончится, а библиотека блюд, правило возврата и твои цифры останутся. Пользоваться ими можно годами.
>
> **1 890 ₽** — один раз, навсегда твоё. Без подписки и доплат.
>
> `[ Написать Эдуарду ]`
>
> *Пишешь мне в личку — отвечаю сам, не бот и не менеджер. Скажу реквизиты, отвечу на вопросы, включу курс.*

Тип старта подставляется по `t` из payload v2: `never` → 🌱 Чистый лист · `quit` → 🔁 Второй заход · `onoff` → ⚡ Рывками. Уровни курса с типом больше не связаны — их проходят все подряд, с первого по четвёртый.

#### Оффер в развёрнутом виде: три слайда

Текст выше — короткая версия в чате. Под ней кнопка `[ Посмотреть курс ]`,
которая открывает Mini App со страницей оффера. Там то же самое, но тремя
слайдами: обложка → ценность → решение. Листаются подряд, точки навигации
справа, на третьем слайде цена, кнопка в личку и семь частых вопросов.

Собирает страницу `offer-page/build_offer.py`, отдаёт три файла:

| Файл | Кому |
|---|---|
| `out/offer-template.html` | разработчику: `{{name}}` и `{{type}}` подставляются из того же JSON квиза |
| `out/offer.html` | посмотреть глазами, с демо-подстановкой |
| `out/offer.pdf` | те же три слайда одним файлом, если оффер шлют в чат вложением |

PDF нужен не вместо Mini App, а рядом: он остаётся в переписке и его
пересылают. Персонализации в нём нет — файл один на всех.

### 5.5 Догрев, если не купил

Отменять всю цепочку, как только человек нажал «Написать Эдуарду»: дальше
разговор идёт в личке, и автоматические напоминания там только мешают.
Джобы вешаются от `quiz_at` — момента, когда человек дошёл до конца теста.

**+4 часа**
> {name}, карточка со стартовой точкой у тебя на руках. Что с ней делать дальше — покажет День 1: полный аудит режима, без единого запрета. 1 890 ₽.

**+24 часа**
> Ты знаешь свою зону риска — {зона}. Знаешь свои окна: {окно1} и {окно2}. Через две недели ты про это забудешь, как забывала прошлые разы, — не из-за лени, а потому что напоминать некому. Курс напоминает каждый день. 14 дней, 1 890 ₽.

**+3 дня**
> Больше на эту тему писать не буду: либо сейчас, либо в другой раз. Если появятся вопросы — я на месте и отвечаю сам. Разбор ситуации бесплатный и без срока.

**+7 дней**
> Прошла неделя. Как дела с теми двумя окнами, {окно1} и {окно2}, — используешь? Если нет, я не удивлён: без структуры они и не должны были заработать. Курс на месте, разбор тоже. Просто напиши.

#### Длинный хвост

Первые четыре сообщения закрывают первые двое суток, пока разбор ещё свежий. Дальше человек не «горячий лид», а просто читатель, который однажды прошёл тест. Пишем редко и по делу, иначе бота отправят в блок и адрес сгорит навсегда.

Правила хвоста, их нарушать нельзя:

* **не чаще раза в две недели**, всего четыре касания, потом тишина;
* **«скоро подорожает» повторяем не больше одного раза** — если бот полгода пишет «бери, пока не подняли», а цена стоит на месте, человек видит, что его водят. Либо цена действительно поднимается, либо эта строка из хвоста уходит;
* **в каждом сообщении хвоста — строка отписки.** `[ Не писать больше ]` выключает всю цепочку и ставит `unsub = true`. Кнопка обязана работать с первого нажатия;
* если человек ответил в чат — цепочка останавливается, дальше живой разговор.

**+14 дней**
> {name}, две недели назад ты {g:прошла|прошёл} тест. Вопрос без продажи: {g:начала|начал} что-то делать или пока думаешь? Если пока думаешь — это нормально, я к тому, что думать можно бесконечно, а День 1 занимает пятнадцать минут.
>
> `[ Написать Эдуарду ]` `[ Не писать больше ]`

**+30 дней**
> Месяц. Твоя зона риска была {зона} — она никуда не делась, я по опыту знаю. Не покупай ничего, просто ответь себе: за этот месяц стало лучше или так же? Если так же — дело не в мотивации, а в том, что не на чем держаться.
>
> `[ Написать Эдуарду ]` `[ Не писать больше ]`

**+60 дней**
> Два месяца назад ты {g:искала|искал} способ начать. Если {g:нашла|нашёл} — рад, правда. Если нет — у меня есть бесплатный разбор, и это не воронка: сажусь, смотрю твою ситуацию, говорю, что делать. Беру несколько в неделю.
>
> `[ Записаться на разбор ]` `[ Не писать больше ]`
>
> Кнопка ведёт в личку с уже набранным словом `РАЗБОР`:
> `https://t.me/Mr_Serbolin?text=РАЗБОР`. Человеку не надо придумывать,
> с чего начать сообщение, а Эдуард по слову видит, что заявка из курса.
>
> **Формат разбора один во всех текстах: созвон 30 минут, бесплатно,
> с документом после.** В ответном сообщении Эдуард просит прислать три
> фото листов — день 1 (карта суток), день 7 (чекпоинт) и день 13 (таблица
> повторов). Без них полчаса на четыре блока не хватает, а человек, который
> уже прислал фото, почти не отваливается перед созвоном.

**+90 дней — последнее**
> Последнее сообщение от меня, дальше не пишу. Курс и разбор на месте, найти можно в любой момент. Удачи, {name}.

После +90 дней джобы не ставятся. Возобновить цепочку может только сам человек — новым тестом или сообщением в чат.

## 6. Продажа в личке

Платёжной системы нет. Кнопка под оффером ведёт в диалог с Эдуардом, там он
называет реквизиты, отвечает на вопросы и включает курс руками. Ни ЮKassa, ни
провайдерского токена, ни `pre_checkout`, ни `successful_payment` в боте нет.

### 6.1 Кнопка

Обычная url-кнопка с заранее набранным текстом. Человек не должен придумывать,
с чего начать разговор, — у него открывается диалог, где сообщение уже
написано, остаётся нажать «отправить».

```python
code = short_code(uid)          # 4 символа, стабильные для этого user_id
text = quote(f"Хочу курс «Первые шаги к форме». Код {code}")
InlineKeyboardButton(
    text="Написать Эдуарду",
    url=f"https://t.me/Mr_Serbolin?text={text}",
)
```

Код нужен, чтобы Эдуард в личке сразу понимал, кто пишет. Юзернейма может не
быть, имя в Telegram может не совпадать с именем из теста, а `user_id` в личку
не передаётся — без кода придётся переспрашивать «а вы тест проходили?».

`short_code` — любая короткая стабильная функция от `user_id`, например первые
четыре символа sha1. Требование одно: по коду находится человек в базе.

### 6.2 Заявка

Нажатие на кнопку — это событие, которое видит бот. По нему он делает две вещи.

**Пишет Эдуарду карточку.** Всё, что нужно для разговора, сразу под рукой:

> 🔔 Заявка · код **A7F3**
>
> Галина, @galina_ok, 36 лет
> Тип: ⚡ Рывками
> Рост 165, вес 78 → 66. ИМТ 28.7
> Окна: 7:30 и 20:00 · зона риска: вечер
> Тест пройден 40 минут назад
>
> `[ Включить курс ]` `[ Отказался ]`

**Ставит человеку метку `awaiting`** — заявка есть, курс не выдан.

### 6.3 Выдача

Эдуард жмёт `Включить курс` — бот отменяет догрев, спрашивает часовой пояс и
ставит 14 джобов. Дальше всё как при автоматической оплате.

Кнопка `Отказался` тоже нужна: без неё непонятно, человек ещё думает или уже
сказал «нет», и он будет вечно висеть в списке ожидающих.

### 6.4 Чтобы никто не потерялся

Ручная выдача ломается не на технике, а на памяти. Три вещи закрывают это:

* **`/waiting`** — список тех, кто нажал кнопку и ещё не получил курс, с
  временем заявки. Открыл — видно, кому не ответил.
* **Напоминание Эдуарду через 2 часа**, если заявка всё ещё висит. Не человеку,
  а себе: «Заявка A7F3 без ответа 2 часа».
* **Ничего не удалять по таймауту.** Заявка живёт, пока по ней не нажали одну
  из двух кнопок.

### 6.5 Что остаётся на Эдуарде

Реквизиты он называет сам в переписке, в боте их нет — так их не увидит тот,
кто просто листает оффер.

**Чек обязателен и здесь.** Перевод на карту не отменяет обязанности выдать чек
при продаже физлицу: самозанятость и чек в «Мой налог» на каждую оплату. Разница
с автоматикой только в том, что раньше чек пробивала касса, а теперь это минута
руками после каждой продажи.

`TXT_PAID` — то же сообщение, что и при автоматической оплате, отправляется по
нажатию `Включить курс`:

> {name}, ты в деле.
>
> Первый урок придёт завтра в 8 утра. Ничего сегодня не начинай — серьёзно, не начинай. День 1 идёт без диеты и без зала, и это не подарок, а часть метода: пять изменений одновременно не выдерживает никто.
>
> Терпение + Дисциплина = Результат. До завтра.

Если сегодня уже позже 20:00 — предупредить, что первый урок утром через день, чтобы человек не ждал письма ночью.

### 6.6 Когда переходить на автоматику

Ручная продажа упирается в одно: заявка в час ночи ждёт до утра, и часть людей
за это время остывает. Пока заявок несколько в день, живой разговор это
окупает — он закрывает возражения, которых кнопка не видит. Когда заявки пойдут
десятками и ответы начнут задерживаться на полдня, включается раздел «Оплата» из
автоматической версии: код бота меняется в одном месте, всё остальное остаётся.

## 7. Выдача курса

**8:00 по времени человека.** Часовой пояс спрашивается кнопками один раз — в
момент, когда Эдуард нажал «Включить курс».

Каждый день:
1. Текст урока — одно сообщение, 5 минут чтения (тексты в `tripvaer-14-dney-Serbolin.md`)
2. PDF-страница дня — отдельным документом
3. **20:00 — чек-ин:** инлайн-кнопки `Сделал` / `Не вышло`

### 7.1 Развилка по цели

Питание в курсе зависит от того, что человек выбрал в тесте. Веток две:
**дефицит** (`gl` = `loss` или `tone`) и **профицит** (`gl` = `mass`).
Тренировки, режим и психология у всех одни — разводить их не нужно.

**В тексте урока** абзацы помечены прямо в спеке: `[дефицит]` уходит первой
ветке, `[профицит]` — второй, без метки получают все. Метку носит абзац, а не
день: в одном уроке общая часть и развилка стоят рядом. Расходятся дни
**2, 3, 6, 7, 8 и 10** — всё это питание.

**В PDF** расходятся три страницы: **3, 6 и 7**. У версии под набор к имени
добавлен суффикс `-nabor`:

| День | Дефицит | Профицит |
|---|---|---|
| 3 | `kurs-03-voda.pdf` | `kurs-03-voda-nabor.pdf` |
| 6 | `kurs-06-golodat-ne-nuzhno.pdf` | `kurs-06-golodat-ne-nuzhno-nabor.pdf` |
| 7 | `kurs-07-pervyy-chekpoint.pdf` | `kurs-07-pervyy-chekpoint-nabor.pdf` |

Имена — из нового набора, тёмного золотого (`build_kurs.py`). Прежний алый
набор `tripvaer-*.pdf` лежит рядом с теми же суффиксами и снимается вместе
с зависимостями, когда новый примут.

**Почему именно эти дни.** У двух целей противоположны ровно три вещи: что
означают неподвижные весы (день 7), зачем считать жидкие калории (день 3) и
куда двигать вечернюю еду (день 6). Сказать это одной формулировкой нельзя —
половине читателей она соврёт. Тарелка, библиотека блюд и правило про любимую
еду общие: у набора к ним дописан абзац, и только.

Цель «привести тело в форму» идёт по ветке дефицита. Отдельная третья ветка
означала бы треть курса ради оттенка, который решается одной оговоркой в
дне 7, — она там уже стоит.

### 7.2 Развилка по полу

Ось вторая и независимая от цели: метки `[ж]` и `[м]` (`g` из payload).
Без метки абзац получают все. Меток у абзаца может быть две сразу —
`[профицит] [ж]` уходит только женщине на наборе.

**Расходится один день — седьмой.** Там абзац про цикл: за несколько дней до
месячных тело задерживает воду, весы показывают плюс килограмм-полтора, и
женщина посреди курса решает, что всё зря. Это самая частая причина срыва у
женщин, и мужчине этот текст не нужен.

Больше в уроках пол не разводит ничего, и это намеренно: питание и психология
у всех одни. Пол меняет три другие вещи — **темп в прогнозе** (см. ниже),
**базовый комплекс** и **программу тренировок** (см. 7.4).

**PDF-страница дня 7 остаётся одна на цель и не делится по полу.** Страница —
бланк для записи, а объяснение адресное: его место в сообщении бота, которое
и так собирается под человека.

**А вот четыре страницы с комплексом делятся: 4, 9, 11 и 13.** Суффикс `-m`
или `-zh` по полю `g` (`m` → `-m`, `f` → `-zh`):

| День | Мужчина | Женщина |
|---|---|---|
| 4 | `kurs-04-pervaya-trenirovka-m.pdf` | `…-trenirovka-zh.pdf` |
| 9 | `kurs-09-vtoraya-trenirovka-m.pdf` | `…-trenirovka-zh.pdf` |
| 11 | `kurs-11-trenirovka-kogda-nekogda-m.pdf` | `…-nekogda-zh.pdf` |
| 13 | `kurs-13-test-progressa-m.pdf` | `kurs-13-test-progressa-zh.pdf` |

Различается одна строка из пяти: у женщин ягодичный мостик, у мужчин на его
месте приседания у стены. Решение владельца. Текст урока при этом один на
всех — он не называет упражнений поимённо, только «комплекс».

### 7.2а Где заниматься

Тест спрашивает это отдельным экраном, во втором блоке — рядом с «сколько
минут» и «сколько раз в неделю». Три варианта: `home`, `gym`, `any`.

**`any` — «ещё не решил» — ведёт в домашний вариант.** Вариант обязателен:
часть людей приходит именно с этим вопросом, и заставлять их выбирать вслепую
значит терять их прямо на экране. Начать дома можно сегодня, а перейти в зал
получится в любой момент — так и написано в ответе бота.

Но перед выдачей программы бот один раз переспрашивает. За две недели человек
мог решиться, и отдать ему домашний вариант, не спросив, — значит промахнуться
на ровном месте. Спрашиваем только тех, у кого `pl` = `any`; выбравшим `home`
или `gym` вопрос не задаём.

> 🏋️ Последнее перед программой. В тесте ты не выбрал, где будешь заниматься.
> По умолчанию соберу домашнюю: ни абонемента, ни оборудования, начать можно
> сегодня вечером.
>
> Но если за эти две недели ты решил идти в зал — скажи сейчас.
>
> `[ Дома ]` `[ В зале ]`

**Дома** → Понял, собираю домашнюю. Перейдёшь в зал позже — напиши, пришлю
зальную, это бесплатно.

**В зале** → Понял, зальная. Если окажется, что до зала пока не доезжаешь, —
напиши, пришлю домашнюю.

Ответ пишем в БД в то же поле `pl`, чтобы вторая выдача не переспрашивала.

### 7.3 Темп прогноза зависит от пола

В `plan()` квиза и в `lib/profile.py` лежит одна таблица:

| | Набор | Похудение, > 15 кг | Похудение |
|---|---|---|---|
| Мужчина | 0,35 кг/нед | 0,7 | 0,55 |
| Женщина | 0,20 кг/нед | 0,55 | 0,45 |

Раньше цифры были общие, то есть женщина получала мужской срок и не
укладывалась в него. Меняешь в одном месте — меняй в обоих: расхождение ловит
`test_profile_parity.py`.

Урок дня 7 намеренно **не называет** темп числом, а отсылает к прогнозу из
теста: иначе при правке коэффициентов текст и расчёт разъедутся. Тот же
принцип, что с нормой КБЖУ.

Реакции на чек-ин:

> **Сделал** → Отметил. {стрик} день подряд. Так и держим.
>
> **Не вышло** → Бывает. Ничего не компенсируем и не догоняем: завтра просто идём по плану. Один пропущенный день ничего не решает, решает выход из графика на неделю.

Ответ на «Не вышло» ни при каких условиях не должен звучать как упрёк. Именно на этом месте люди отваливаются от курсов, а у нас на 12-й день стоит урок «Как не бросить», который весь построен на «один пропущенный день не равен провалу». Тон должен совпадать заранее.

**День 14** — итоги Точка А → Точка Б, честные границы курса и приглашение на бесплатный разбор.
**Дни 15, 18, 25** — три касания с предложением онлайн-ведения.

### 7.4 Программа тренировок и разбор

После урока четырнадцатого дня человек получает ещё два файла: свою программу
и страницу разбора. Это уже не уроки, а то, что остаётся на руках.

**Программа — один файл из восьми.** Выбирается тремя полями payload:

| Поле | Значение в квизе | Кусок имени файла |
|---|---|---|
| `pl` | `home`, `any` → дом; `gym` → зал | `dom` / `zal` |
| `gl` | `loss`, `tone` → похудение и тонус; `mass` → масса | `pohudenie` / `massa` |
| `g` | `m` / `f` | `m` / `zh` |

`kurs-15-programma-{dom|zal}-{pohudenie|massa}-{m|zh}.pdf`

Внимание на две подмены: `f` в payload превращается в `zh` в имени файла,
а `any` в `dom` — но только после уточняющего вопроса из 7.2а.

Похудение и тонус получают одну программу: разница между этими целями живёт
в питании, а не в упражнениях. Развилка та же, что в 7.1, — считать её второй
осью не нужно.

**Видео с техникой.** В PDF карточка упражнения целиком — ссылка: нажал,
открылось видео. Для тех, кто читает с компьютера или с распечатки, под
сообщением с программой дублируем ссылки url-кнопками, по две в ряд, подпись
кнопки — название упражнения. Ссылки берутся из `serbolin-pdf/data/atlas.py`,
там же лежат приписки к пяти роликам, где снаряд на видео отличается от того,
что человек делает у себя. Приписку ставим текстом рядом с кнопкой, иначе
человек решит, что попал не туда.

**Страница разбора** — `kurs-16-razbor.pdf`, идёт следом за программой, тем же
сообщением, что и приглашение на созвон.


События для аналитики: `start`, `sub_required`, `sub_ok`, `quiz_open`, `quiz_step_N`, `quiz_done`, `day0_done`, `offer_shown`, `contact_clicked`, `course_granted`, `declined`, `day_N_read`, `checkin_done`, `checkin_failed`, `review_requested`.

Главные цифры на старте: **упёрся в подписку / прошёл её / дошёл до конца теста / сделал День 0 / написал в личку**. Первые две показывают цену гейта: сколько людей ушло на подписке. Если разрыв большой, вопрос не к тесту, а к тому, объяснил ли ты, зачем подписываться. Четвёртая появляется сразу за ними и на ручной продаже важнее всех: **сколько заявок дошло до оплаты**. Если люди пишут, но не платят — разговор ломается там, где раньше стояла кнопка. Если тест бросают — смотри на каком шаге, экраны 8–11 самые тяжёлые. Если делают День 0, но не платят — проблема в оффере, а не в трафике.
